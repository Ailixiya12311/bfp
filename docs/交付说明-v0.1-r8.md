## 2. Windows 本地运行

在项目目录使用 PowerShell。凭据输出目录须尚不存在：

```powershell
.\bin\bfp-v0.1-r8.exe keygen -out .\credentials-local
```

分别在两个终端启动：

```powershell
# 终端一
.\bin\bfp-v0.1-r8.exe server -config .\credentials-local\server.json -stats 1s

# 终端二
.\bin\bfp-v0.1-r8.exe client -config .\credentials-local\client.json
```

默认服务地址为 `127.0.0.1:51880`，同时监听 UDP/TCP；客户端 SOCKS 地址为 `127.0.0.1:1080`。默认先 UDP，建连失败或活动路径失效后使用同认证服务器 TCP。切换适用于有效期内的存活内存会话与目标 socket，允许短暂停顿；旧 Session 已销毁后新 Connect 是新网络，旧流不能迁入。

默认出口策略拒绝私网/loopback/特殊地址；localhost fixture 必须显式允许并将 CIDR/端口限制到实验目标，详见[实现进度](实现进度.md)。SOCKS 支持 CONNECT/UDP ASSOCIATE，非零 FRAG 丢弃。真实 Mihomo/sing-box/TUN/fake-IP/IPv6/DNS 完整矩阵与原生 outbound 仍待完成。

配置包含私钥和秘密。keygen 与配置读取执行平台私有权限检查、链接拒绝、大小/未知字段/尾随校验；不得把配置放入公共证据或交付 ZIP。SOCKS 无本地认证，当前保持 loopback。文档不附带 SSH 或设备凭据。

## 3. 分类器与配置范围

Go `ClientConfig.Classification` 和 `ServerConfig.Classification` 可配置独立策略；nil 使用默认。Client/Session 公开 `DialClass`、`DialMetadata`，Flow 提供 actor 内只读分类快照。可信域名、规则标签与 Hint 只来自本地 API；wire 值不成为服务端可信来源，服务端独立分类自己的下载 TX。

唯一新增接受的应用字节驱动分类，控制、填充、重传、恢复补传不计。UDP 所有分片原子入队；任一预算拒绝不耗编号、不残留半报。实际 owner Tick 管理滑动窗口与空闲恢复，承载恢复保留原分类器与累计量，真实空闲仍可改变当前类。类别只影响调度，不修改目标授权或交付语义。

**本二进制 CLI JSON 未开放 classification 或 socks_metadata。** CLI 与 SOCKS 使用默认本地策略；下一阶段方案中的字段会被当前配置读取拒绝。阶段 B 的版本化类别公告/确认、PeerTXAnnounced、能力协商尚未实现。

已开放的生命周期 options 仍只有 `ticket_ttl`、`ticket_refresh_lead`、`ticket_overlap`、`max_session_lifetime` 正 duration 字符串；缺省使用默认。完整条件见[会话凭证生命周期](会话凭证生命周期.md)。Go 进程内撤销 API 与固定最大会话寿命保留，刷新不延长旧凭证绝对有效期，也不轮换准入秘密或恢复 PSK。

## 4. 验证与继续开发边界

每条 probe UDP 最多一次 Write，在第一次 Stats 之前起算 1s 绝对截止；跳过无关/迟到回包不续期，失败仍计入总门槛。`write_accepted` 只表示完整 net.Conn API 返回，读阶段包含关联与截止检查，不能当作目标执行证明或纯 RTT。

r7 固定 Write deadline 快照和 TCP incoming 背压修复沿用；动态 deadline、并发 writeMu 等待可取消、actor 同步 TCP 写入/2s socket deadline 与 TCP 压力边界仍存在。r8 没有实现 ACK ranges/PTO、最终信用/确认可靠重试或 TCP 无条件 stream 重排改进。[UDP 可靠控制方案](UDP确认与可靠控制实现方案.md) 及隔离 r9 组件属于后续开发，未进入本候选。

有限未授权样本证明本 run 的 16 UDP/8 TCP 无应用响应、无新目标连接；TCP 仍能握手、部分连接会 reset，不能保证主动探测绝对无法识别。LIGHT 填充、首包准入、AEAD 与防重放保留原实现边界，SHAPED/COVERED/FEC/自动 TCP→UDP 为原设计可选，不作新增强制门槛。

独立 race 通过且两机资源清理完成，不覆盖本次 WAN 业务失败。当前无 r8 ZIP，历史 r5/r6/r7 失败保持各自记录；后续改动应新建修订、独立冻结验证。完整目标还包括可靠控制、认证 profile/类别版本、入口与全局资源预算、真实集成、性能/长时稳定性、确定性向量/互操作和独立安全评审。
