# r8 分类器阶段 A 接线实现

日期：2026-10-07。状态：**阶段 A 已合入主源码，主 r8 独立本地与 Linux race PASS，WAN 严格 FAIL，无 ZIP**。本文描述真实 Go API 与 owner 提交合同，不以设计方案、staging 或本地测试宣布 r8 完整通过。合入记录为 [source-changes.json](../verification/merges/r8-classification/source-changes.json)：从 r7 的 56 文件增加到 61 文件，5 个新增、8 个修改，没有删除；改动限于 Session 与 scheduler。主代理独立构建、本地/race/WAN 的结论见 [r8 验收记录](验收记录-v0.1-r8.md)。稳定 TCP 承载上的首次 UDP 超时与后续迟到关联保留；本轮 WAN 不触发默认大流分类，不能推导分类器网络性能。

## 1. 本阶段落地与后续范围

已有纯 `classification` 组件现在接入每条生产 Session flow 的本地发送方向。普通拨号走本地规则，显式 Hint 受本地 cap，持续新增业务量使用有限滑动窗口与迟滞，空闲时可恢复初始基线。两个端点分别拥有自己的策略和观察量，类别只影响调度，不修改目标授权、TCP/UDP 交付语义、拥塞/流控、FIN/RESET 或消息边界。

| 范围 | 当前真实行为 | 本阶段没有完成的部分 |
|---|---|---|
| Go 配置/API | Client/Server 编译固定本地策略；公开 DialClass、DialMetadata 和分类查询 | CLI JSON 分类参数、可信 SOCKS/Clash 元数据桥接 |
| 行为观察 | 每方向接受的唯一应用字节、实际 owner 单调 Tick、降级/恢复 | 最大流数下 Tick CPU、真实混合负载公平性/尾延迟基准 |
| 恢复 | 原 classifier/baseline/累计量/origin 随同 Session 保留；真实空闲可改变当前类 | 阶段 B 类别版本、确认、对端公告视图与能力协商 |
| 调度 | 新业务按本地类，控制保持 Interactive，同 flow FIFO | data-only backlog 即时迁移、独立控制队列/预算、Session 更细配额配置 |
| UDP 准入 | PushBatch 一次验证全部 queue 配额；拒绝无半报/编号/统计副作用 | 动态 Write deadline、writeMu 等待可取消等既有 Transport 扩展 |

[分类器接入方案](分类器接入方案.md) 保留 r6 期间的分阶段设计与历史源码现状。其 A/B/C 目标不全部等于本次实现；阶段 B 和后续队列/适配器能力仍须各自设计、冻结和验证。

## 2. 构造配置与默认语义

`ClientConfig.Classification`、`ServerConfig.Classification` 均为 `*classification.Config`。NewClient/NewServer 在创建连接/监听资源前验证策略，并持有不可变编译副本；规则与端口切片不保留调用方可变引用。Server 策略错误优先于 Listen，返回 `classification.ErrConfig`。每个新 Session 使用对应 Client/Server 编译策略，每条 flow 行为状态仍由其 Session actor 独占。

| 配置输入 | 真实语义 |
|---|---|
| `Classification: nil` | `classification.DefaultConfig()`；默认 Normal、最高可为 Interactive、启用候选行为参数 |
| 非 nil 显式配置 | 按显式值校验，不自动套 DefaultConfig |
| `&classification.Config{}` | 零值类别为 Interactive，行为 Enabled=false；是有效的显式策略，区别于 nil |
| `DefaultConfig()` 后关闭 Behavior.Enabled | 保留 Normal 默认、规则及 cap，禁用行为调整 |
| `HighestAllowed: Normal` | Hint/规则至多得到 Normal；允许 Normal/Bulk，不能提升至 Interactive |

默认候选行为参数如下；这些是实际算法参数，不是已验证的网络性能指标：

| 参数 | 默认值与用途 |
|---|---|
| Window / Bucket | 4s / 250ms，有界滑动时间桶；配置约束 2–1024 桶、窗口不超过 1min |
| MinTotalBytes / Bulk rate | 至少 1MiB 新接受累计量，同时窗口达到 256KiB/s 候选门槛 |
| BulkSustain / ActivityGap | 持续候选 3s，新字节观察间隔至多 1s；单次突发不能仅凭留在窗口里自动达成持续活动 |
| Restore / low rate | 开启恢复；窗口低于 64KiB/s 门槛后持续 8s |
| Cooldown | 改类之间至少 5s，恢复回本地初始基线 |
| Locked baseline | 禁止行为调整，仍统计接受的业务字节 |

r7 的“累计 sendNext 超过 1MiB 且距上次改类大于 1s 就转 Bulk”分支已由阶段 A 接线替换。r8 仍有 MinTotalBytes 条件，但它与窗口、持续活动和迟滞共同成立，不能继续把当前实现描述成单一累计阈值。

## 3. 拨号、信任和服务端独立策略

| 公开入口 | 本地分类合同 |
|---|---|
| Client/Session `DialContext(ctx, network, address)` | 无可信 Hint，走本地 network/port 规则与默认策略 |
| Client/Session `DialClass(ctx, target)` | 将 Target.Class 作为本地可信 Hint，仍受 HighestAllowed；不是 wire 授权 |
| Client/Session `DialMetadata(ctx, meta)` | 由本地适配器/API 指定 DomainTrusted、RuleTagTrusted、Hint.Trusted；Session 在提交 actor 前复制 Hint |
| `Session.FlowClassification(ctx, id)` / `Flow.Classification(ctx)` | actor 内返回本地 TX 快照副本，不返回可写 classifier 指针 |

分类优先级为可信 Hint → 可信域名/规则标签规则 → network/port 规则 → 默认。规则按 Priority 排序，相同 Priority 保留配置次序；域名须由调用者转换成 ASCII DNS 名。目标 network/address/port 仍做结构检查，可信域名/tag/hint 非法时不分配 flow ID、不增加 Opened、不发送 OPEN/拨号目标。

可信标记只来自本地入口，不序列化到 OPEN。认证设备发来的 Target.Class、Domain、RuleTag 不成为服务端可信政策来源。服务端按自身规则/cap 建立下行 TX classifier，并保留原始 OPEN target 用于重复 OPEN 的身份比较；类别变化不改目标、不重新拨号。线上 Class 必须符合现有结构值域，即使它不决定服务端的本地发送类别。

示意 Go 配置片段：

```go
policy := classification.DefaultConfig()
policy.HighestAllowed = protocol.Normal
policy.Rules = []classification.Rule{
    {Name: "local-call", DomainSuffix: "example.test", Class: protocol.Interactive},
}
client, err := session.NewClient(session.ClientConfig{
    Server: serverAddress, Credentials: credentials, Classification: &policy,
})
// 完整地址、凭据和错误处理仍由调用方提供；CLI JSON 尚无此字段。
```

SOCKS 本身没有可信 Clash rule tag 或应用身份。现有 adapter/CLI 使用默认策略；不能因为线上携带域名就自动设置 DomainTrusted，也不能从本阶段推导已完成 Mihomo/sing-box 原生接入。

## 4. 唯一应用字节与提交边界

客户端 flow 统计上传 TX；服务端的目标 Read 经 `flow.Write` 统计下载 TX。每个方向独立，不在 bridge、Flow.Read 或接收重组处重复 Observe。

| 路径 | Observe 与副作用 |
|---|---|
| TCP | 通过信用/缓冲/deadline 检查并追加 chunks 后，按实际 accepted part 计一次；每 part 至多 900B |
| TCP 部分 Write 超时 | 已接纳的前缀计入，未接纳尾部与等待不计；返回 n 对应真实已接纳字节 |
| UDP | 所有分片 batch 成功准入后，messageNext 推进一次，Observe 原整包 payload 长度一次 |
| 空 UDP | 提交一个边界消息并推进编号，业务字节增加 0 |
| 拒绝 UDP | oversize、deadline、编号耗尽、任一 queue 配额失败均不推进编号、不 Observe、不留下该报分片 |
| 未就绪 UDP | 保留原 best-effort 丢弃并可返回完整 API 长度的行为；丢弃不进入分类统计 |
| 协议/补传 | 头、padding、控制、ACK、重传、恢复重新排队不计为新接受业务 |

因此 `write_accepted` 的 probe API 语义仍不等于内部分类准入，更不证明线上发送或目标执行。Observe 的时间异常会取消 Session；正常生产使用 Go time.Now 的单调分量，计数饱和而不环绕。

## 5. Tick、查询和恢复

Session 保存带单调分量的 classOrigin；Observe/Tick 在 actor 实际处理时采样 classNow，避免积压 ticker 的旧时间导致倒退。生产 owner 的 10ms timer 即使没有写入仍维护窗口和恢复迟滞，terminal flow 不再 Tick。单个窗口受桶数上界限制，但最大 streams 下 CPU 仍待实测。

FlowClassification 快照包含 ID、Network、LocalTX 和 Terminal。LocalTX 含 Baseline、Class、Elapsed、TotalBytes、WindowBytes；查询只取 Snapshot，不推进 Tick。未知 ID 返回 `ErrFlowUnknown`，已关闭 Session 返回 `ErrClosed`，没有 classifier 的合成/拒绝 tombstone 返回 `ErrState`，调用取消返回 context 错误。

attach/recover 保留原 Session、Flow、classifier、baseline、累计应用量和 classOrigin。恢复重新发送相同字节偏移不再次计数，原目标 socket 不因改类重建。维护在 suspended 状态也执行，所以真实空闲可能使当前 Class 恢复；“保留分类状态”不代表生产暂停 Tick 或冻结当前类别。恢复 fixture 固定时钟用于区分状态替换与自然空闲演变。

## 6. 调度、batch 原子性与 legacy 兼容

STREAM_DATA/DATAGRAM 使用本地流类；OPEN、FIN、credit、RESET、同步、换钥等控制保持 Interactive。pre-sync、congestion、record retransmit 三条重排分支使用 classForFrame，避免控制占用 Bulk 预算。

排队期间保留 item 原类和同 flow FIFO；没有对混合队列调用 ReclassifyFlow。数据实际重新排队时取当前本地类。Interactive 控制类别不表示它能越过同 flow 较早的数据，data-only backlog 迁移与独立控制资源合同仍待后续。

`scheduler.PushBatch` 在任何 mutation 前验证 class、正费用、费用累加上界，以及总/每 flow/每 class bytes 和 items、flow 数量。全部通过后才创建 ring/flow 并 append。任一失败保留旧值、类别费用/项数、ring/cursor/deficit；UDP messageNext 与 Observe 在 batch 成功之后才更新。实现依赖 queue owner confinement，queue 不是并发安全容器。Session 当前仍使用原总字节构造器；新增 batch 支持细配额原子性，不等于 CLI/Session 已配置所有细配额。

阶段 A 不发送新的分类公告；legacy CLASS_UPDATE 作为兼容 no-op 消费，不修改本地 TX，结构版本、OPEN 与恢复 wire 没有新增字段。类别版本、ACK、乱序/重复最新状态合并、PeerTXAnnounced、能力协商与恢复同步属于阶段 B，尚未实现。
