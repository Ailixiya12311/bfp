## 本轮实现与确定修复

1. Ticket 固定 TTL、服务器内存 locator 刷新和客户端安装 ACK、独立 serial、固定旧 alias 过渡窗口、严格使用时到期检查。恢复 secret 保持 Session 作用域不变。
2. 首次 IK 设备授权绑定延续到 PSK 恢复。Go `RevokeDevice` 与握手提交线性化，撤销覆盖缓存 INIT/READY、候选提交、活动会话和晚到刷新；返回后已登记目标 socket 关闭。
3. 会话最大截止从首次 INIT 固定，恢复、刷新、重复激活不延长。关闭后 `Client.Connect` 创建新网络；旧流报告关闭，不迁入新 Session。
4. CLI 的 server/client/probe 支持四个可省略生命周期 duration 字符串，错误字段明确，沿用私有权限与严格配置读取。
5. 调度改为类别外层总字节权重 4:2:1、同类流内部等权 DRR。纯 `classification/` 组件已完成可信规则、有限滑动窗口和迟滞；Session 仍使用原累计字节分类，组件接线尚未完成。
6. 新接入文档固定 Mihomo v1.19.32 与 sing-box v1.14.2 官方源码基线，具体 native outbound、carrier dial hook 与真实软件矩阵仍未实现。

独立对抗测试发现已关闭初始 Session 仍可返回缓存回复/READY。修复加上所有候选的关闭/取消状态复查。原失败 `verification/ticket-adversarial-first.jsonl` 保留。

r4 的全包准备失败，`verification/v0.1-r4/validation.json` 为 `pass=false`：新加入的持续 flow 清空重入回归触发 scheduler 饥饿，45 秒超时。修复按逻辑轮转尾插入新 flow/category，并有两层热重入回归和旧数组回收测试。没有生成 r4 二进制，也没有将其失败改为通过。

生命周期末尾另修复连续刷新：已确认 Ticket 若已覆盖全部剩余最大寿命，不再因提前量重复旋转；未取得 ACK 时仍重发原固定 issue，到最大截止照常关闭。

## Linux 竞态与双机 WAN

Linux race run `f7f613dfa8fa034ba9d83609f5af1b61`：54 个冻结 Go/模块文件与本地构建/当前源码逐项一致，11 包竞态测试 PASS、exit 0，owned 容器与目录精确清理，执行总时间 128.501 s。原工具 `pass=false` 是 LA 原有动态 UDP 端点变化；完整保存前后 owner 后，补充 review 逐项确认全部变化均为原有 Xray PID 17883，高位 UDP 以外固定监听、容器、路由、防火墙一致。原始 gate 不改写。

WAN run `0387f1ac577e411ad6b1d3edbb4e643c`：两机上传同一 r5 ELF，TTL 12 s、提前 8 s 刷新、旧 alias 6 s、最大寿命 5 min。每场业务时间超过原 12 s TTL，并记录安装刷新；不过严格 UDP 全成功门槛没有满足。

原始 `wan-result.json`、逐场 evidence、完整日志及 `udp-failure-analysis.json` 保留。后续测量修复不得取消最初的超时、延长 1 s 操作期限或把 r5 写成 PASS；新源码需要新修订验证。

随机 UDP 16 个、TCP 8 条无认证样本应用响应为 0，目标连接无新增。LA 2 个、SG 6 个 owned 进程以及两个临时目录/秘密已全部清理。SG baseline 完全一致，LA 唯一差异为既有 Xray 动态 UDP，saved owner 补充审查确认固定服务配置稳定。WAN `code_checks_pass=false` 及原始总体 false 均保留，不能用静态配置通过覆盖业务失败。

## 验收边界

当前是阶段交付，不是整个技术方案的最终完成。已实现 Ticket locator 生命周期不代表准入秘密或恢复 PSK 轮换，也不提供泄露后安全恢复。Go 撤销 API 不等于远端管理控制接口；未提交 TCP 候选按有界握手期限回收；任意忽略 context 的自定义 Backend 迟到 socket 由失败回调随后关闭，API 即时资源保证限于已登记目标连接。

新增必需 `u/e/l` 字段与帧 22/23，双方须使用同一修订；r3 与 r5 不应混用。完整 ACK ranges/PTO、分类器会话接线/类别版本、profile 协商、真实 Mihomo/sing-box/IPv6/DNS/fake-IP/TUN、全局预算/压力/长时稳定性、向量/互操作与独立安全评审仍待推进，见[需求验收清单](需求验收清单-v0.1-r5.md)。FEC、SHAPED/COVER、自动 TCP→UDP 与跨进程恢复按设计作为后续扩展记录。
