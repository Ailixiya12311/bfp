# BFP v0.1-r3 交付与运行说明

这是直接使用 UDP/TCP 的独立 Go 实验协议。客户端首先尝试 UDP；建连或活动路径失效后，接到同一服务端的 TCP。恢复只适用于仍在内存中保留的会话与存活目标连接，业务允许短暂停顿。正式名称、稳定 wire 和生产安全结论仍待后续冻结。

## 文件与证据入口

- `bin/bfp-v0.1-r3.exe`：Windows amd64 客户端/服务端/实验 CLI。
- `bin/bfp-v0.1-r3-linux-amd64`：Linux amd64 同构建。
- `docs/验收记录-v0.1-r3.md`：当前构建的本地、Linux 竞态、双机 WAN 以及清理边界。
- `docs/实现进度.md`：API、CLI、配置字段和当前设计差异。
- `docs/wire-v0.1.md`、`docs/密码与准入规范.md`：实验帧/握手/记录规则。
- `verification/v0.1-r3/validation.json`：当前摘要、测试和对应证据的机器可读入口。

双机实验固定洛杉矶 `192.0.2.10` 为接收/出口、新加坡 `198.51.100.20` 为发送。测试服务使用独立临时目录和进程；实验结束即精确清理，不作为常驻部署。凭据不包含在交付包中。

## Windows 本地运行

在项目根目录使用 PowerShell。输出凭据目录必须尚不存在，生成程序不覆盖已有内容：

```powershell
.\bin\bfp-v0.1-r3.exe keygen -out .\credentials-local
```

终端一启动服务端，默认同时监听 `127.0.0.1:51880` 的 UDP/TCP：

```powershell
.\bin\bfp-v0.1-r3.exe server -config .\credentials-local\server.json -stats 1s
```

终端二启动客户端，默认在 `127.0.0.1:1080` 提供 loopback SOCKS5：

```powershell
.\bin\bfp-v0.1-r3.exe client -config .\credentials-local\client.json
```

生成的出口策略默认拒绝 loopback、私网和特殊地址。访问公网目标可通过 SOCKS5；需要在本地验证 echo 时，按实现进度配置 `AllowPrivate: true` 并限定到具体 CIDR 和 fixture 端口。当前实现支持 SOCKS CONNECT 和 UDP ASSOCIATE；FRAG 非零丢弃。Mihomo/sing-box 可以通过本机 SOCKS 出站接入，原生 BFP outbound 尚未实现和验证。

默认客户端和服务端都仅为本地实验配置。双机部署需要自行设置明确监听地址、同一服务器的 UDP/TCP endpoint 和出口策略；远端测试的临时配置不可用于后续生产部署。不要把 no-auth SOCKS 接口暴露到公网。

`keygen` 使用 Linux/Unix 的当前用户私有权限，Windows 使用原生 owner-only、禁止继承的 DACL。读取导入配置会拒绝链接、不安全 owner/权限、过大文件、未知字段和尾随 JSON。编辑配置后须保持权限。配置包含私钥和秘密，Base64 不是加密；不要提交或打印到共享日志。

## 重新构建

模块声明 Go 1.26.0，当前验证工具为 Go 1.27.0。源码与构建变化后需要建立新证据，不能沿用旧二进制结果：

```powershell
go build -trimpath -o .\bin\bfp-local.exe ./cmd/bfp
go test ./... -count=1 -timeout=45s
go vet ./...
go mod verify
```

本地 Windows CGO 关闭不能直接运行 race；已有 Linux 竞态结果关联冻结源码清单。短时测试、LIGHT 填充和有限无认证探测均不代表生产成熟度或长期不可识别，实际限制见验收记录。
