# BFP v0.1 成品运行与部署

这份说明对应项目根目录当前 Go 成品和 `build.ps1` 生成的 Windows/Linux amd64 包。它描述能直接运行的路径，协议成熟度仍按代码和验收记录逐项提升。

## 先做本机自检

在解压包的 `bin` 目录执行：

```powershell
.\bfp-windows-amd64.exe version
.\bfp-windows-amd64.exe demo
```

`demo` 不访问公网、不写凭据文件。它在内存中生成一次性密钥，启动本地 BFP server、SOCKS5 入口和 TCP/UDP echo 出口，输出 `demo_pass` 且 `fallback_carrier` 为 `tcp`，才算认证 Session、默认 UDP 承载、初始 UDP 失败后的 TCP 接管、TCP 流、UDP 流和 SOCKS TCP 入口都走通。

## 生成跨机器配置

建议在受信任的管理机上生成一次凭据，然后通过受保护的文件传输分别放到两台机器。下面使用当前测试角色：洛杉矶 `192.0.2.10` 作为接收/出口机，新加坡 `198.51.100.20` 作为发送/客户端机。

先在管理机生成：

```powershell
.\bfp-windows-amd64.exe keygen `
  -out .\bfp-credentials `
  -server-listen 0.0.0.0:51880 `
  -server 192.0.2.10:51880 `
  -tcp-server 192.0.2.10:51880 `
  -socks 127.0.0.1:1080 `
  -classification-profile low-bandwidth
```

生成的 `server.json` 只放洛杉矶，`client.json` 只放新加坡。不要把两个文件都复制到两台机器，也不要把文件内容放进日志或工单。服务端防火墙只放行预期的 UDP/TCP 端口；本项目不会替你修改防火墙、路由、DNS 或系统代理。

`low-bandwidth` 预设把 UDP 53 和 TCP 22 固定为 Interactive，其他流初始为 Normal；累计至少 32 KiB 且持续满足 8 KiB/s 阈值时归为 Bulk，持续低于 2 KiB/s 后恢复。判定使用 4 秒窗口、3 秒高速持续期、8 秒恢复持续期，并受活动间隔和冷却时间约束。它只调整分类/调度，不是限速器。默认 `standard` 保持旧行为。根 preview.22 和原生 Mihomo preview.31 共用这份 JSON 策略；若 Mihomo YAML 显式提供 classification，它会整体替换 JSON 策略。

两台测试机运行 Linux。上传 Linux 程序到各自主目录下的专用 `bfp` 目录，给程序执行权限，再启动。洛杉矶启动：

```sh
chmod +x ./bfp-linux-amd64
./bfp-linux-amd64 server -config ./server.json -stats 5s
```

新加坡启动：

```sh
chmod +x ./bfp-linux-amd64
./bfp-linux-amd64 client -config ./client.json
```

客户端会在本机监听配置中的 SOCKS 地址。这里默认是新加坡机器本机的 `127.0.0.1:1080`。在新加坡机器上可以用小请求验证公网访问：

```sh
curl --proxy socks5h://127.0.0.1:1080 --max-time 15 https://example.com/
```

若从自己的 Windows 电脑使用新加坡上的客户端，需要把该回环入口通过 SSH 转发到本机，例如 `ssh -N -L 1080:127.0.0.1:1080 用户名@198.51.100.20`，然后在本机应用里填写 SOCKS5 `127.0.0.1:1080`。也可以直接在自己的电脑上运行 BFP 客户端，使用洛杉矶服务端配置。新加坡是当前发送测试机，测试保持小流量。

目标出口策略由 `server.json` 的 `policy` 控制。默认策略不允许私网和 loopback，联调时要在服务端明确写出受限的 `allowed_cidrs` 和 `allowed_ports`。

## 可选的会话 DNS A/AAAA 入口

在客户端配置的根对象中增加 `dns` 字段：

```json
{
  "dns": {
    "listen": "127.0.0.1:1053",
    "mapping_ttl": "10m",
    "mapping_capacity": 64
  }
}
```

重新启动客户端后，同一端口提供 UDP/TCP DNS。A 使用 `198.18.0.0/15`，AAAA 使用 `fd42:6266:7000::/96`。两个地址归属同一条 Session 映射，重复查询不续租，TTL 同时受映射和 Session 的实际期限限制。把响应地址经该客户端的 SOCKS5 入口使用时，会还原成原域名再交给出口解析；DNS 回答的地址族不强制改变真实出口地址族。

Linux 有 dig 时可做小请求检查：

```sh
dig @127.0.0.1 -p 1053 example.com A
dig @127.0.0.1 -p 1053 example.com AAAA +tcp
```

入口接受单个 IN A/AAAA 问题和标准 EDNS(0)，dig 的默认查询可以直接使用。UDP 响应最大 1232 字节，小于 512 的 EDNS offer 按 512 处理；传统 DNS 的 UDP 上限为 512。未实现的 Cookie、Padding、ECS 等选项忽略且不回显，不参与出口目标选择。当前不支持 MX/TXT/PTR 或 DNSSEC 验证；DO 提示保留，但答复不置 AD/AA/RA。旧 Session、过期、未知或带 zone 的临时地址不能进入出口拨号。入口不修改系统 DNS、TUN 接口或操作系统路由。

## 构建自己的包

```powershell
.\build.ps1 -Version 0.1.0-preview.5
```

输出目录和同名 ZIP 包含 Windows/Linux amd64 二进制、`source/` 根 Go 模块源码、`source-manifest.json`、`release-manifest.json`（文件大小和 SHA-256）、产品说明和本部署说明。包不包含凭据。输出已存在时脚本会报错，使用新的版本号或输出目录即可。

## 当前产品边界

已经可以运行的是独立 Go client/server、认证 Session、多流、默认 UDP、同服务器 TCP fallback、SOCKS5 TCP/UDP 接入、加密记录、首包准入和生命周期约束。2026-10-10 已有两轮新加坡→洛杉矶有限 WAN 记录，覆盖三个承载场景；此前 UDP 超时失败记录保留。完整 TUN/native outbound、IPv6 WAN、混合分类负载、长期稳定性和安全审查仍未完成。本机 `demo_pass` 覆盖初始 UDP 失败后的 TCP 回退，不能替代运行中切换和这些系统验收；细节见 [产品说明](../PRODUCT.md)。
