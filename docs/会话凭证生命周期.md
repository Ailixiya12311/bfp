# BFP 会话凭证生命周期

日期：2026-10-07。范围：当前 Go 实验 v0.1 实现的 Ticket 有效期、主动刷新、设备热撤销和 Session 最大寿命。本文依据 `session/ticket.go`、`server.go`、`client.go`、`bootstrap.go`、`session.go` 及本地回归记录编写；它是实现合同和验证说明，不是独立安全审计或已冻结的跨实现互操作规范。

## 1. 凭据、身份和会话的作用域

首次接入使用 Noise IK：客户端固定服务器静态公钥，服务器检查首次 IK 客户端静态公钥对应的设备授权。Session 保存该设备的服务器内部 authority；以后通过恢复 PSK 接入，仍属于这个首次获授权设备。热撤销作用于这个 authority，不能通过只持有旧 Ticket 或通过恢复握手绕过。

Ticket 是密码学随机的 128-bit 定位符，以 32 个十六进制字符表示。服务器内存记录把它绑定到同一服务器实例、Session、首次 IK 设备、凭据序号和固定到期时间。Ticket 本身不构成恢复授权；恢复仍须证明持有该 Session 的独立 32 B `resume_secret`，完成 Noise NNpsk0、新挑战和来源绑定确认。

本次刷新只轮换 Ticket 定位符，`resume_secret` 在 Session 生命周期内保持不变。每次新 Carrier 仍通过新 Noise 握手获得新方向密钥。Ticket 序号 `TicketSerial` 独立于 Carrier 的 `Generation`：刷新凭据不增加承载代次，恢复承载也不能把较新的凭据退回旧版本。这一行为不应称为恢复 PSK 轮换或泄露后的安全恢复。

Ticket、PSK、设备 authority、Session 和出口连接均属于当前服务器实例的内存状态。服务器重启后旧恢复资格失效，不能凭 Ticket 重新拨号并把新出口连接当作原连接。

## 2. 四种独立期限

| 选项 | 默认值 | 含义 |
|---|---|---|
| `TicketTTL` | 20 分钟 | 一份当前 Ticket 的独立有效期 |
| `TicketRefreshLead` | `TicketTTL / 4`，默认 5 分钟 | 距 Ticket 到期不足该时间时，健康活动会话开始刷新 |
| `TicketOverlap` | `min(30 秒, TicketTTL / 4)`，默认 30 秒 | 轮换后的旧定位符最多保留的过渡窗口 |
| `MaxSessionLifetime` | 24 小时 | Session 从首次 INIT 分组建立起的固定最大寿命 |

另外，`RetainTimeout` 默认 30 秒，用于无承载或恢复同步未完成的会话；`HandshakeTimeout` 默认 3 秒，用于单次握手。它们都与 Ticket TTL 分开管理。

服务器对初始 Ticket 使用 `min(首次 INIT 时间 + TicketTTL, Session 最大截止)`。刷新后新 Ticket 使用 `min(本次首次签发时间 + TicketTTL, 原 Session 最大截止)`。最大寿命从首次 INIT 固定，比从 READY 或同步完成计时更保守；后续 confirm、attach、activate、刷新、恢复和重复 READY 都不能重新起算。

独立 Ticket 到期只取消该定位符的恢复资格，不直接关闭健康活动 Session。健康且双向恢复同步完成的活动承载可以继续业务并领取新的定位符。没有活动认证承载时，过期定位符不能授权刷新；会话同时受原无承载保留期限与最大寿命约束。

最大寿命到期、设备撤销或 Session 主动关闭会终止会话及所属流和出口资源。Client 后续 `Connect` 会丢弃已经关闭或 context 已取消的 current Session，执行新的首次接入；新 Session 有新的 ID、Ticket、临时逻辑地址和初始承载代次，旧流不会迁入新网络。

当前参数校验要求：Ticket TTL 与最大寿命为 40 毫秒至 30 天；刷新提前量至少 1 毫秒且小于 TTL；过渡窗口至少 1 毫秒且不大于 TTL。0 使用默认值，负值及越界值拒绝。测试可以使用较短期限，但生产默认值保持上述设置。

## 3. 时间权威和客户端本地截止

服务器用本地 `time.Time` 的单调时钟成分保存权威到期时间。判断有效资格时要求 `expires.After(now)`，因此恰好到期也无效；使用时立即检查，不依赖后台清理是否已经删除记录。

Noise 加密的 Session 参数新增：

| JSON 字段 | Go 字段 | 含义 |
|---|---|---|
| `u` | `TicketSerial` | 当前 Ticket 的非零单调凭据序号 |
| `e` | `TicketRemainingMS` | 当前 Ticket 剩余有效毫秒数 |
| `l` | `LifetimeRemainingMS` | 原 Session 最大寿命的剩余毫秒数 |

服务器 authority、issuer 指针与本地绝对截止不进入 JSON。剩余毫秒向下取整，0 或超过 30 天的线上 TTL 拒绝。客户端从本次握手开始时间映射本地截止，使握手耗时包含在可用期限内；业务恢复后的合并只保留更早的最大寿命截止。

活动刷新把服务器当时计算的剩余 TTL 映射为客户端接收时刻后的本地单调截止，并受原最大寿命约束。重复同序号刷新只允许保留或收紧已经安装的截止，不能每次接收后重新延长。网络传输延迟仍可能使第一次活动刷新安装的本地估计略晚于服务器截止；本地截止用于调度，恢复授权始终由服务器判定。客户端墙钟不能延长服务器资格。

## 4. 主动刷新、逻辑确认和丢失

服务器只在活动承载健康且双向同步完成后进行主动刷新。到达提前刷新时点且没有未完成的签发操作时，服务器先在注册表中登记新定位符，再通过活动加密记录发送它。签发在 `Server.mu` 内复查设备撤销、Session 注册身份和最大寿命，避免撤销删除被晚到的 actor 签发重新覆盖。

当前内部帧约定：

| 编号 | Kind | 字段与语义 |
|---|---|---|
| 22 | `TicketRefresh` | 服务端到客户端；`flags=0`、`flow=0`、`value=TicketSerial`、`offset=剩余毫秒数`、`data=32字符定位符` |
| 23 | `TicketRefreshAck` | 客户端到服务端；`flags=0`、`flow=0`、`value=已经安装的序号`，其他字段为空或0 |

客户端先验证并安装新凭据，再发送逻辑确认。同序号不同定位符属于冲突，终止会话；较低序号不能覆盖当前凭据。服务端只用与当前 pending 序号匹配的 ACK 完成安装确认；未来或过时序号不能改变 pending。角色错误、字段错误或非法 TTL 拒绝。承载的 `PACKET_ACK` 不能代替安装 ACK。

一次 pending 签发的定位符、序号和绝对截止固定。逻辑确认丢失时，服务端重发同一凭据并根据原截止重新计算剩余毫秒数。重试节奏为 `max(10 毫秒, min(1 秒, TicketTTL / 8))`；只有成功入队才更新发送时间。重发不会产生新定位符，也不会延长该次有效期。客户端重复收到同序号时重新 ACK，且本地截止不会向后移动。

如果未确认的新定位符已经到期，健康认证承载可以放弃该 pending 并签发下一份。该权限来自仍有效的活动承载，不来自过期定位符。每 Session 的注册表最多保留当前和一个过渡定位符；新的轮换会清除更旧的 alias。

若新Ticket被最大寿命截短，且已获安装确认的当前截止恰好等于Session最大截止，服务器不再轮换已经覆盖全部剩余寿命的凭据。这样即使剩余寿命短于刷新提前量，也不会在每次ACK后立刻再次签发。尚未取得ACK的pending仍按原规则重传；该优化不能延长最大寿命，也不能跳过到期关闭。

旧定位符的截止为 `min(旧原截止, 首次轮换时间 + TicketOverlap)`。因为旧原截止本就不超过 Session 最大截止，过渡窗口也不能跨越最大寿命。ACK 丢失、旧定位符重试和重复轮换确认均不延长它。ACK 到达本身不提前删除仍在固定过渡窗口内的旧 alias。

## 5. 严格到期、恢复尝试和提交

本版采用严格到期，没有过期后的 retry-only 例外。正常 INIT、命中已存在 pending 的缓存 INIT、首次 confirm、queued attach 执行以及已提交候选的缓存 READY 都需要有效资格。恢复候选绑定实际使用的 locator，检查服务器注册表中的当前截止；轮换缩短旧 alias 后，已经创建的 pending 不能继续依靠旧快照有效期提交。

恢复操作按 Session ID 和 attempt ID 去重，Ticket 只用于定位与资格验证。因此同一次合法恢复在切换 UDP/TCP、改变新候选来源或更换仍有效的 alias 后，仍属于原操作。恢复去重记录本身有界，不能成为永久恢复凭证。

actor 成功 attach 就提交该操作的承载代次，即使 READY 随后无法完成。若 attach 后资格复查失败，会话进入固定保留期；原 operation 使用另一个有效 alias 重试，仍使用已经提交的代次，不能再次增加。新建 Session 的 attach 失败则取消该新对象，避免留下未激活会话。READY 的创建和网络交付依旧不等于恢复同步完成，业务开放仍受双向快照和 Done 确认门槛约束。

READY 丢失后，如果仍有效的原定位符或另一个有效 alias 可用，同一次恢复可以重试而不重复增加代次。如果所用 locator 已经到期，即使操作曾提交，也拒绝缓存 INIT/READY；客户端不能用“这是重试”继续延长资格。没有任何有效 locator 时，旧 Session 最终受保留期限和最大寿命约束，后续首次接入产生新网络。

握手回复仍遵守 UDP 防放大预算。当前最长凭据值与最大序号的真实 Noise 回归得到：reply 最大952 B，新建 INIT 最小1121 B、恢复 INIT 最小1120 B。UDP confirm使用内部JSON填充，最小1121 B且整体不超过1200 B；READY最大464 B。服务器所有 bootstrap 应答仍不超过对应输入数据报。

## 6. Go 热撤销 API 和并发边界

管理接口为 `(*Server).RevokeDevice(public []byte) error`，输入为已配置的32 B客户端静态公钥。它是当前进程内的 Go API；本版没有与之等价的远程命令、远程CLI或管理网络端点。

撤销对当前 Server 实例永久生效：后续首次 IK、恢复 INIT、pending confirm、缓存 READY和凭据签发都必须拒绝该设备。API 在设备 gate 内更新原子 revoked 状态、取消该设备的 Session 并删除所有关联 Ticket；解锁后等待 Session `done`。confirm注册与attach提交使用同一gate，actor不等待该gate，仅检查原子撤销状态；签发和删除共享服务器注册表锁，避免反向等待。

撤销返回时，所属 Session 已停止，已经登记在 Session 中的目标套接字已执行关闭。当前调用不会等待所有外部 backend 工作自行退出。如果自定义 `Backend.DialContext` 忽略取消，它可能在撤销返回后才返回一份尚未登记的迟到连接；Session回调检查取消状态或发现actor已经结束后关闭该连接。该 API 不保证不合作 backend 永不返回迟到结果，也不保证其外部工作已经结束。生产 backend 应遵守context并自行限制拨号资源。

尚未提交的 TCP 首包连接或握手候选不因撤销立即全部从注册表中移除或关闭。它们受原握手读取期限、候选清理期限及64槽限额约束，撤销资格检查阻止提交；不能把这一边界描述为所有未认证TCP连接已经在撤销返回前结束。最大寿命关闭同样依赖 Session 清理已登记资源；已经取消的外部拨号仍按迟到结果规则释放。

热撤销状态不持久化到磁盘。重启若仍把同一静态公钥列入新服务器的 AllowedClients，会重新创建未撤销authority；需要跨重启撤销时，管理员须同步修改服务器授权配置。不要在日志中记录静态私钥、准入秘密、resume secret、完整Ticket或握手原文。
