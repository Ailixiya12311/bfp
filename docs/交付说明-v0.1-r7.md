## 2. Windows 本地运行

以项目根目录作为 PowerShell 工作目录。凭据输出目录须尚不存在，程序不会覆盖已有目录或文件：

```powershell
.\bin\bfp-v0.1-r7.exe keygen -out .\credentials-local
```

在两个终端启动服务端和 loopback SOCKS5 客户端：

```powershell
# 终端一
.\bin\bfp-v0.1-r7.exe server -config .\credentials-local\server.json -stats 1s

# 终端二
.\bin\bfp-v0.1-r7.exe client -config .\credentials-local\client.json
```

默认服务地址 `127.0.0.1:51880`，同时监听 UDP/TCP；SOCKS 地址 `127.0.0.1:1080`。默认出口拒绝私网、loopback 和特殊地址。本地 fixture 实验须显式 AllowPrivate，并将 CIDR/端口限制到目标。SOCKS 支持 CONNECT/UDP ASSOCIATE，FRAG 非零丢弃；真实 Mihomo/sing-box SOCKS/TUN 支持矩阵及 native outbound 尚未验收/实现。

双机运行需明确监听地址、同一出口的 UDP/TCP 地址与出口策略；本轮临时远端服务已清理，不是常驻部署。TUN 应排除 BFP carrier 端点与相关控制流，完整接入行为仍待真实软件验证。

## 3. 生命周期配置

`keygen` 生成完整默认配置。server/client/probe JSON 顶层可增加可省略的 `options`：

```json
{
  "options": {
    "ticket_ttl": "20m",
    "ticket_refresh_lead": "5m",
    "ticket_overlap": "30s",
    "max_session_lifetime": "24h"
  }
}
```

这是 options 片段，完整启动仍需地址、credentials 与适用的出口 policy。字段省略使用默认；已给字段必须为正 Go duration 字符串。TTL/最大寿命为 40ms–720h，提前量至少 1ms 且小于 TTL，overlap 至少 1ms 且不大于 TTL。未知字段、null、数值、空字符串和非法值不会静默选默认，错误标字段和规则、不回显配置值。其他 `session.Options` 尚未全部开放为 CLI JSON。

Ticket 到期禁止使用该 locator 恢复，健康活动会话可刷新；最大 Session 寿命从首次 INIT 固定，到期关闭。后续 `Connect` 可创建新网络，旧流失败、不迁入新 Session；Connect 的调用 context 仅限制本次建连。Client 自身 Close 后不能重启该 Client。服务端 `RevokeDevice` 为 Go 进程内 API，无远端管理 CLI；locator 刷新不轮换准入秘密或恢复 PSK。

配置包含私钥和秘密。Windows 使用当前用户 owner 与受保护 DACL，Unix 校验私有 owner/mode；读取拒绝链接、不安全权限、超限及未知/尾随 JSON。编辑后保持权限并使用可信目录；no-auth SOCKS 保持 loopback。本交付说明不包含可使用的设备秘密或 SSH 凭据。

## 4. Probe、Transport 修复与重新构建

fixture、出口策略限定和黑洞 relay 用法见[实现进度](实现进度.md)。每条 UDP 业务消息至多发送一次，原 deadline 从第一次 Stats 之前的 `udpStarted + 1s` 计算，总 probe 截止可缩短它。无关回包在原截止内跳过；首次失败计数保留，后续成功不回填。

r7 增加 `write_attempted`、`write_accepted`、write/read 阶段时长、`error_phase` 和前后 Stats/exchange 时长。`write_accepted` 仅代表 `net.Conn.Write` 完整返回，不能证明 Session 准入、线上发送或目标执行。读取阶段包含关联与时间检查，不能当作纯 RTT；分段毫秒独立取整。失败阶段分为设置 deadline、写入前、写入、读取前和读取；遥测只输出规范编号、计数与固定错误分类，无原始回包内容。

固定 deadline UDP 准入可取消被 actor 排队阻塞且尚未提交的请求，不消耗消息编号或留下分片。当前合同仍有范围：deadline 在取得 `writeMu` 后快照，期间动态重设与锁等待截止尚未实现；inactive UDP 的 best-effort API 接受语义保持。TCP 完整记录在 incoming 满时背压等待，取消/关闭可退出；同步 actor Write 和现有 2s carrier 写 deadline 仍可能在双向压力下触发 suspend。完整边界和前后证据见[r7 验收](验收记录-v0.1-r7.md)。

改动源码后应创建新修订、独立冻结和验证，不沿用本稿二进制摘要：

```powershell
go test ./... -count=1 -timeout=45s
go vet ./...
go mod verify
go build -trimpath -o .\bin\bfp-local.exe ./cmd/bfp
```

模块 Go 1.26.0，本轮验证工具 Go 1.27.0。上述本地命令不包含 race；本稿 race 证据来自独立 Linux 冻结 run。

## 5. 尚待完成与历史边界

当前类别总字节份额 4:2:1，再同类流等权 DRR。纯可信规则/滑动窗口/迟滞分类器尚未接入这组 r7 Session、SOCKS 或 CLI；阶段 A 后续开发隔离在 staging，不能算入 r7 已实现能力。类别版本、可靠控制/ACK ranges/PTO、认证 profile 协商、全局/来源/设备预算、完整异步任务清理、真实接入、性能/长期稳定性、确定性向量/互操作和独立安全评审仍需推进。FEC、SHAPED/COVERED、自动 TCP→UDP 保持原设计可选，不新增门禁。

综合状态为 `WAN_STRICT_FAIL_NO_ZIP`。两项受控 Transport 回归通过没有消除本轮实网第一次 UDP 失败；阶段遥测不能确定 relay/目标的精确丢失点，也没有证明 r6 首次延迟根因。r5/r6 原验收与失败保持历史原值；后续新修订应独立冻结、构建和验证，不把旧失败回填为通过。
