### 3.2 WAN 严格结果、迟到回包和宿主清理

| 场景 | TCP / UDP 成功 | UDP failed | 业务时间 | 安装刷新 | 严格结论 |
|---|---|---:|---:|---:|---|
| [正常 UDP](../lab/runs/05af448101c740a483d1c6692cabb220/normal_udp.evidence.json) | 50/50；50/50 | 0 | 35.268s | 8 | PASS |

三场保留同 Session/临时地址和一个原目标 TCP socket，并跨原凭证 TTL。正常为 UDP gen1；运行切换为 UDP gen1→TCP gen2、一次 switch；初始黑洞直接使用 TCP gen1。最大 TCP 写读操作时间分别为 547/4887/1263ms，包含整个操作，不能将 4887ms 直接解释为精确切换暂停、纯 RTT 或 p99。

[udp-operation-phase-analysis.json](../lab/runs/05af448101c740a483d1c6692cabb220/udp-operation-phase-analysis.json) 校验三场 150 次完整、有序进度、非负阶段计时、布尔值与 raw 成败计数，同时绑定 validation 的 Linux 摘要。初始黑洞场 [probe-log.json](../lab/runs/05af448101c740a483d1c6692cabb220/initial_udp_blocked.probe-log.json) 的唯一失败是 iteration 14：

- 操作前后均为 TCP gen1，`write_attempted=true`、`write_accepted=true`；API Write 与前后 Stats 各记录 0ms，独立毫秒取整不等于完全无耗时。完整 Write 返回不证明内部准入、线上发送或目标执行。
- `error_phase=read`、`error_kind=timeout`，read/exchange/overall 均为 1000ms，未关联到当前回包，没有无关/迟到回包。原截止耗尽后第一次失败立即保留。
- iteration 15 先跳过规范编号 14 的迟到回包（`unmatched_count=1`、`late_count=1`），再匹配当前 15，overall 186ms、read 185ms，通过；前后仍为 TCP gen1。它证明后续关联能恢复，也证明编号 14 的回包在后续调用内可被读取，不能确定它在第一次 Read 截止前还是之后进入各级缓存，更不能反推精确网络/actor/目标延迟原因。
- 运行切换场 42 次稳定 TCP 前后观察全部成功；初始黑洞场 50 次稳定 TCP 中 49 次成功。全部三场只记录这一次无关/迟到回包；有限样本不保证未来零超时。

默认分类器累计下限为 1MiB；每场每个可靠 TX 仅 50×16KiB=819200B，故 WAN 不触发默认大流降级。本轮验证新代码对基础会话/载体路径的兼容，分类行为转换的证据来自真实 localhost runtime 回归；这次实网既不测量混合类别公平性，也不能据未触发降级证明分类器性能。分类修订没有实现新的可靠控制或 TCP 压力改进；稳定 TCP 的迟到回包根因仍未确定。未续期 probe 截止、重发该业务或以 iteration 15 的成功回填 14；没有对不变二进制重跑以挑选全通过样本。

[udp-failure-analysis.json](../lab/runs/05af448101c740a483d1c6692cabb220/udp-failure-analysis.json) 仍按工具固定定义分析运行切换场，该场无失败；初始黑洞失败由 phase analysis 单独保存，不能混淆两份分析的场景。

有限未授权探测中，16 UDP 无应用回包，8 TCP 成功连接后无应用响应，部分 timeout、部分 reset；不能写成没有任何网络响应或主动探测绝对不可识别。目标连接累计 3→3，无新增出口副作用。洛杉矶 2 个、新加坡 6 个 owned 进程全部停止，两机 run 目录及其中秘密删除。[supplemental-baseline-review.json](../lab/runs/05af448101c740a483d1c6692cabb220/supplemental-baseline-review.json) 的两机 raw baseline 均 `unchanged=true`，固定服务、容器、路由、防火墙配置稳定。原 WAN false 来自业务失败，不来自宿主差异；清理/基线通过不覆盖此失败。

新增 Session 回归使用实际 NewClient/NewServer、安全握手/记录、loopback 目标和生产 bridge；特定 admission/queue 配额隔离仍包含 owner test seam。无 sockets 的 requeue fixture 检查的是状态和预算，不伪装成 WAN 性能。正式单元 Fuzz pass 事件只代表种子执行；独立 fuzz campaign 如执行应另登记。

## 5. 当前范围与历史边界

CLI JSON 未暴露分类配置，可信 SOCKS/Clash Domain/RuleTag/身份桥接、真实 Mihomo/sing-box/TUN/DNS/fake-IP/IPv6 尚未验收。阶段 B 的分类版本、ACK、对端公告视图与恢复/乱序合同未实现。Session 当前总字节 queue 构造器保留，细配额 batch 能力不等于已部署每类/每流/项数/设备预算；真实 fairness/goodput/p95/p99 与最大 streams Tick CPU 仍待测量。

r7 固定 Write deadline 快照、动态重设/writeMu 等待、TCP 同步写入与 2s carrier deadline 等边界保留。分类接线不会使 UDP 变可靠，也不证明目标事务只执行一次。FEC、SHAPED/COVERED、自动 TCP→UDP 仍为原设计可选范围。
