## 2. 从 r2 到 r3 的确定修复

1. **正常双向 FIN 释放目标 socket**：两条 bridge 任务都退出后，使用共享 `sync.Once` 完整关闭目标。单向 EOF 保持反向传输；正常结束不发 RESET，可靠数据及 FIN 状态仍等待协议确认。之后 Session/RESET 清理不会重复调用底层 Close。
2. **合法 UDP CONFIRM 为 READY 提供足够预算**：r2 的 CONFIRM 可以仅 374 B，而缓存 READY 最多 464 B，抗放大限制会静默抑制较长回复。真实网络诊断确认连续三个合法小确认仍无回复。r3 只给 UDP 确认补充认证内部填充，最小 1121 B、实际不超过 1200 B；READY 必须不大于收到请求的限制保留。TCP、Noise 证明和生产默认 3 s 超时未更改。
3. **逐次 UDP 测试观测**：probe 每个 iteration 记录成功/超时、耗时、操作前后 carrier/generation 和实验相对时间。它反映应用操作边界，不等于数据报送达确认或丢失发生时刻。严格 PASS 条件保持 TCP 全部成功，启用 UDP 时还要求全部成功且 failed=0。

## 6. 历史证据与结论边界

[r2 验收记录](验收记录-v0.1-r2.md)的独立 WAN 严格 FAIL：运行中 UDP→TCP 时 TCP 50/50、同一 Session 和原目标 socket 保留，但 UDP 49/50，failed=1；正常/初始 UDP 黑洞均 TCP/UDP 50/50。现有旧日志不能精确定位丢报，r3 的逐操作观测补足这一缺口。此 FAIL 和准备阶段 SSH 中断/遗漏源码失败均保留原记录，不覆写、不通过重复采样改为通过。首次较早构建三场 PASS 也不用于证明新源码。

当前实现覆盖独立 Go client/server、默认 UDP/同服务器 TCP 恢复、多流可靠字节与尽力 UDP、会话认证复用/换密钥/恢复秘密、会话临时资源、三类 DRR、LIGHT 填充、防主动探测准入、loopback SOCKS5。原生 Mihomo/sing-box、IPv6/fake-IP/TUN 完整矩阵、完整 ACK ranges/PTO 与性能公平性、Ticket TTL/刷新/热撤销、全局资源压测和长时稳定性仍需开发/验证。

SHAPED/COVER、FEC、自动 TCP→UDP 回切、跨进程恢复、mesh/二层网络未实现。分类是简单累计大流阈值，调度是加权 per-flow DRR。密码封装含自有实验构造，尚无独立安全审计与跨实现互操作结论。加密/静默不隐藏 IP/端口、包长、方向、时序和 TCP 内核响应，有限无响应扫描不能证明长期不可识别。

Session.Close 会关闭登记资源并使 Flow 失败；握手/写 socket 受 deadline 限制，关闭不是瞬时；当前没有等待全部 bridge/dial 工作任务退出的统一 WaitGroup。内置 net/gateway 使用上下文和关闭传播，任意不合作自定义 Backend 不属于固定退出时间保证。
