## 4. 本轮 WAN 严格失败与关联修复证据

独立 run `97e1e70f41907588de12dcfdc038cf9f`：[wan-result.json](../lab/runs/97e1e70f41907588de12dcfdc038cf9f/wan-result.json)，总耗时 303.398s，原始 `pass=false`。两机实际 ELF 摘要为本稿所列 r6 Linux 文件。生命周期 TTL 12s、提前 8s、旧 alias 6s、最大寿命 5min；每场 50 次 TCP 16KiB 和 50 次小 UDP 业务消息，间隔 250ms。

| 场景 | TCP / UDP 成功 | UDP failed | 业务时间 | 客户端安装刷新 | 严格场结论 |
|---|---|---:|---:|---:|---|
| [正常 UDP](../lab/runs/97e1e70f41907588de12dcfdc038cf9f/normal_udp.evidence.json) | 50/50；50/50 | 0 | 50.690s | 12 | PASS |
| [运行中 UDP→TCP](../lab/runs/97e1e70f41907588de12dcfdc038cf9f/udp_to_tcp.evidence.json) | 50/50；49/50 | 1 | 39.318s | 8 | FAIL |
| [初始 UDP 黑洞→TCP](../lab/runs/97e1e70f41907588de12dcfdc038cf9f/initial_udp_blocked.evidence.json) | 50/50；50/50 | 0 | 36.088s | 9 | PASS |

三场均保持同 Session/临时地址，每场只新增并继续使用一个原目标 TCP socket，均跨原 Ticket TTL 并安装刷新。正常 UDP gen1，切换 UDP gen1→TCP gen2，初始黑洞 TCP gen1。最大 TCP 操作时长分别 2917/4218/1146ms，包含整次写读，不能作为纯切换暂停或尾延迟统计。

切换场 [probe-log.json](../lab/runs/97e1e70f41907588de12dcfdc038cf9f/udp_to_tcp.probe-log.json) 与 [probe-correlation-analysis.json](../lab/runs/97e1e70f41907588de12dcfdc038cf9f/probe-correlation-analysis.json) 给出修复的实网证据：

- iteration 46 前后稳定 TCP gen2，1000ms 到期，`error_kind=timeout`、`success=false`，未收到无关回包，仍计入失败；首次延迟原因未确定。
- iteration 47 在同一 TCP gen2 用 170ms 成功；`last_unmatched_iteration=46`、`late_count=1`、`unmatched_count=1`、`received_iteration=47`，说明丢弃迟到 46 后匹配 47。
- 46 不因 47 恢复成功而回填；整场依然 UDP 49/50、failed=1、严格 FAIL。没有延长 1s 截止或业务重传来消除失败。

因此 r6 验证了相关性修复能够阻止一次迟到回声持续串位，但没有解释或消除首次 1s 超时，也不能从三场有限样本推导所有网络可用或完整性能指标。

## 6. 历史与整体验收边界

[r5 验收记录](验收记录-v0.1-r5.md) 与[需求清单](需求验收清单-v0.1-r5.md) 继续保留 r5 三场原值：正常 UDP PASS，切换 UDP 24/50、初始 TCP UDP 20/50 两场 FAIL。r4 scheduler 超时与 r2 UDP 49/50 失败也保持原始结果。r6 后续结果按新 ELF 独立解释，不覆盖旧失败。

分层调度为类别总字节份额 4:2:1，再同类流等权字节 DRR，已经接入 Session；纯可信规则/滑动窗口/迟滞分类器尚未接线，当前仍为原类别提示与累计字节阈值。分类器下一阶段方案见[分类器接入方案](分类器接入方案.md)，方案本身不计为已实现能力。

Ticket 固定 TTL、逻辑刷新/安装 ACK、严格 alias 截止、Go 设备撤销和最大寿命已经落地；locator 刷新不轮换恢复 PSK/准入秘密。`Connect` 在当前 Session 关闭或其内部 context 取消后可建新 Session，旧流失败，不迁入新网络；Client 自身 Close 后不能重启该 Client。Connect 调用方的 context 只限制本次建连，不是成功 Session 的生命周期 context。

ACK ranges/PTO/可靠最新控制合同、类别版本/预算、认证 profile 协商、全局与来源/设备资源限额、全部异步任务回收、真实 Mihomo/sing-box/TUN/IPv6/DNS/fake-IP、性能/长时稳定性、确定性向量/互操作和独立安全评审仍须连续推进。FEC、SHAPED/COVERED、自动 TCP→UDP 保持原设计可选范围，不新增强制门禁。
