# BFP 源码仓库

此仓库保存独立 BFP 协议、Go 客户端与服务端、Mihomo 原生接入、Windows 客户端脚本、构建工具、测试和技术文档。协议默认使用 UDP，失败后使用 TCP 承载；线上协议不依赖 QUIC、VLESS 或 WireGuard。

公开内容中的服务器地址使用 RFC 5737 文档保留地址，例如 `192.0.2.10` 和 `198.51.100.20`；用户名路径使用 `developer` 等通用名称。它们不是作者的真实测试环境。历史实测结论保留，原始地址、凭据及未经脱敏的运行证据仅保存在本地。

当前属于开发预览版。应用代理已有真实 HTTPS 与洛杉矶出口验证记录；Windows 全局 TUN 能启动和恢复，但最新已执行的 debug07 / attempt07 仍发生 TLS 握手失败。该次运行耗时 30.84 秒，网卡、物理 DNS、默认路由和客户端资源恢复通过；未进入强杀恢复场景。四类需求均未完成最终验收，不能将源码上传视为成熟版本发布。详见 [项目状态](../README.md)、[产品范围](../PRODUCT.md)与[Windows TUN 说明](Windows全局TUN-v0.1.md)。

## 构建与检查

根模块声明 Go 1.26.0，Mihomo 子模块要求以其 `go.mod` 为准。本机此前使用 Go 1.27.0；远端构建环境应使用满足两个模块要求的 Go 工具链。

```powershell
go build -o bin/bfp.exe ./cmd/bfp
go test ./...
```

Mihomo 原生源码在 `integrations/mihomo/source`，其 `replace bfp => ../../..` 指向仓库根模块。原生构建示例：

```powershell
Push-Location integrations/mihomo/source
go build -tags with_gvisor,no_tailscale -o ../../../bin/mihomo-bfp.exe ./
Pop-Location
```

完整便携包通过 `integrations/mihomo/build.py` 和 `deploy/build-client.ps1` 构建。构建与部署的详细参数分别见 [原生接入说明](Mihomo原生接入-v0.1.md)和[部署说明](../deploy/README.md)。以上为仓库使用说明，本次上传没有重新运行协议验收或公网测试。

## 本地配置与证据

Git 不保存 `credentials*`、`deploy/current.json`、`deploy/runs`、`lab/runs`、运行日志、生成的验证结果、源码快照、编译缓存、诊断客户端副本或 `dist` 中的发布包。它们仍保留在原工作区，不会因上传被删除。

远端管理脚本须显式设置 `BFP_RECEIVER_HOST`、`BFP_SENDER_HOST`，可使用 `BFP_RECEIVER_SSH_PORT`、`BFP_SENDER_SSH_PORT` 配置 SSH 端口（默认 22），以及 `BFP_RECEIVER_KNOWN_HOSTS`、`BFP_SENDER_KNOWN_HOSTS` 指定已核对的主机密钥文件。凭据清单由 `BFP_INVENTORY_PATH` 指定，不进入 Git。便携客户端打包时须提供自己的 `-PublicEndpoint` 与 `-ExpectedExitIp`。

发布前执行 `python tools/check_public_snapshot.py --ref HEAD` 检查首次提交是否含有个人服务器地址或用户名路径。该检查保留上游公开样例和常用公共 DNS 测试网段，不触发网络请求。

文档中指向 `verification` 生成结果、`deploy/runs` 或 `dist` 包的链接是原工作区的证据索引，克隆仓库后不会自带这些文件。仓库保留验证脚本、测试和说明；真实运行结果必须由相应记录确认。用户需另行生成或提供自己的客户端和服务端配置，不得将本机凭据提交到 Git。
